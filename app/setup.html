Whoop Pilot setup

BetaFPV Meteor65 Pro II (DJI O4) · DJI Goggles 3 · RadioMaster TX15 (EdgeTX) · Mac + Chrome. About 20 minutes, one time, plus a capture of your house if you want missions. Nothing to solder, no parts to buy.

How it fits together. The app on your Mac watches the drone's video, understands your voice (Claude), and decides stick movements. It sends those to your TX15 over the USB-C cable; a small script on the radio feeds them into the normal ELRS link, but only while your AI switch is on. Flip the switch off, or move a stick, and you're flying again.

1. Radio: install the bridge script

Download aibrg.lua

  1. Plug the TX15 into the Mac, choose USB Storage, and copy aibrg.lua into SCRIPTS/MIXES/ on the radio's SD card. Eject, unplug.
  2. SYS → Hardware → Serial ports → USB-VCP: set to LUA (it's usually CLI; set it back to CLI whenever something else needs the radio's USB serial, such as flashing ELRS through the radio).
  3. EdgeTX 3.0 hides the Mixer Scripts page by default: in the model's Model Settings → Enabled Features, turn Mixer Scripts on.
  4. Select your Meteor65 model. On its Mixer Scripts page, add aibrg and set its inputs:
    InputSet to
    Ail, Ele, Thr, Rudthe model's inputs I0–I3 (Ail, Ele, Thr, Rud), so trims carry over
    AI swa switch you can find by feel with goggles on. On a TX15, SD: down = AI allowed. (SF is a spring-loaded button there, so it can't hold AI on.)
    PTToptional: a momentary button to talk to the drone from the radio. On a TX15, SF.
  5. Mixes: keep your normal line on each channel and add a second line under it:
    ChannelSourceWeightSwitchMultiplex
    CH1 Ailaibrg AIro100SD↓Replace
    CH2 Eleaibrg AIpi100SD↓Replace
    CH3 Thraibrg AIth100SD↓Replace
    CH4 Rudaibrg AIya100SD↓Replace
    Flight-mode channel (CH6 on BetaFPV's model)MAX−100 for the ANGLE position (SA up on BetaFPV's model)SD↓Replace
    The last line puts Betaflight in ANGLE (self-level) whenever the AI is on, which the AI needs. This assumes the usual AETR channel order and that ARM stays on its own switch, which the script never touches.
  6. Check on the bench, props off, in the radio's channel monitor: with SD up, everything behaves as before. With SD down and the app closed, the sticks still move CH1–4 (the script passes them through) and CH6 jumps to the ANGLE position.
  7. Plug USB-C into the Mac and choose USB Serial (VCP). The radio keeps transmitting normally in this mode.

Betaflight / ELRS

  • The AI flies in ANGLE (self-level) mode. Make sure you have a switch for it, or use the AImd line above.
  • In the ELRS Lua script on the radio, set Telem Ratio to 1:8 (or 1:4) so battery and heading arrive several times a second.
  • On the radio's Telemetry page, run Discover new sensors once with the quad powered, so the script can read battery and heading.

2. Video: Goggles 3 straight into the app

Whoop Pilot reads the Goggles 3 live view itself; there's no viewer app or driver. Whoop Pilot's local server (tools/whoop.mjs, Node.js, started by start.command) talks to the goggles over USB-C or over the goggles' own Wi-Fi and hands the H.264 to the app on the same address, which decodes it. The server does this part because Chrome refuses the goggles' USB network interface: it's USB class 0xE0 (wireless controller), one of the WebUSB spec's protected interface classes, and Chromium blocks those for every web page (WebUsbServiceImpl::GetProtectedInterfaceClasses), so no page can claim it.

USB-C (recommended: least delay, and it charges the goggles)

  1. Once: install Node.js with Homebrew: brew install node.
  2. Double-click start.command. One window, one server: the app, the goggles video, the flight recorder and your captures. Keep the window open; closing it stops Whoop Pilot.
  3. Goggles on, drone powered and linked, goggles showing its camera. In the goggles' menu (press the 5D button): Settings → About → OTG Wired Connection off (the default; that mode is for DJI Assistant and footage export, and there's no live view on the cable then), and Share Liveview to Mobile Device via Wi-Fi on (push the 5D button backward for the shortcut menu): despite the name it also turns on the live view over USB (SquirrelReceiver and Goggles3-USB-Livestream need it on for wired too; the manual's “no wired connection while it's on” is about a phone on the cable).
  4. Connect the goggles' USB-C port to the Mac with a data cable (charge-only cables won't work).
  5. In Whoop Pilot: Real drone. The app asks the server for the goggles while the goggles panel is showing and connects by itself; Connect goggles does the same right away.

Wi-Fi instead of USB

The goggles share the same live view over their own Wi-Fi hotspot. No cable, but more delay than USB and the goggles don't charge.

  1. On the goggles, push the 5D button backward from the FPV view for the shortcut menu and turn on Share Liveview to Mobile Device via Wi-Fi. It uses 5.8 GHz, so it's unavailable where that band isn't allowed (Japan, says the manual).
  2. Join the goggles' network from the Mac's Wi-Fi menu. The manual (Liveview Sharing → Wireless Connection with Mobile Device) only covers joining through DJI Fly on a phone, which finds the goggles and joins for you (hold the goggles' power button for 2 s when prompted the first time); it doesn't give the network's name or password or say where to read them, so we can't either. While on that network the Mac has no internet unless it has another connection (Ethernet), and Claude needs internet.
  3. Start Whoop Pilot from a terminal with --wifi: ./start.command --wifi (or cd tools && node whoop.mjs --wifi). The goggles are at 192.168.2.1; --peer IP overrides.
  4. Connect goggles in the app as above.

What the goggles status means

  • Server not running: /goggles/status doesn't answer: start.command isn't running or Node.js is missing (its window says so; brew install node).
  • No goggles on USB: the server runs but sees no DJI device. Data cable? Goggles on? OTG Wired Connection off?
  • The goggles don't answer: the link is up but the goggles ignore the LiveView handshake. Usually one of: the drone is off or not linked (nothing to share); the goggles are asleep, since their proximity sensor turns the screen off when they're not on your head (manual, Overview) and the shared view stops with it (wear them, or rest them so the sensor is covered); Real View or the album is open, which the manual says pauses sharing; the wrong settings for the transport (both: Share Liveview to Mobile Device via Wi-Fi on; USB: OTG Wired Connection off; Wi-Fi: the Mac on the goggles' network).
  • Connected, but no picture: the goggles answer but send no video. Power the drone and check the goggles show its camera.
  • Goggles went quiet: the stream stopped; the app reconnects on its own.
  • Starting the decoder: video arrives. The goggles never send a keyframe (they refresh the picture gradually), so the app bootstraps its decoder with one instead.
  • The decoder took none of the start pictures: Chrome refused every start picture, on the hardware and the software decoder. Click Connect goggles to try again; if it keeps happening, replug the drone battery.

Diagnostics: close the start.command window first (the goggles serve one client), then cd tools && node goggles.mjs probe (add --wifi for Wi-Fi) connects for 9 s and reports packets, resend requests, losses, frames, and whether video kept flowing past the point where the old ACK stalled. node goggles.mjs capture 10 records 10 s to goggles-capture.h264 and describes the stream; it also writes goggles-capture-bootstrapped.h264, which ffplay can play from the start (analyze goggles-capture.h264 redoes both for a saved file). Without goggles, both say so and stop.

Try direct USB (Settings → Camera) asks Chrome for the goggles directly. On Goggles 3 Chrome answers that the interface is protected, as expected; the option is there for other goggles or firmware that expose the network interface differently.

Other goggles (N3, 2, Integra): show DJI Fly's live view on your phone, mirror the phone to the Mac (iPhone Mirroring, AirPlay or scrcpy), and use Capture a window… in Settings → Camera, then Crop to video.

Field of view / tilt: the O4 lens is a 159° diagonal fisheye, 127° across at 4:3 (the default). Set your camera's uptilt (15–35° on the Meteor65 Pro II's mount) if it's far from 20°. Turn and rotation details are learned automatically in flight.

Protocol details for the LiveView session come from dji-goggles-lab (reimplemented from its documentation; that repo has no license file, so none of its code is used) and orbit-rs (MIT). Goggles menu names and behaviour are from the DJI Goggles 3 user manual (v1.0, 2024-05).

3. The app

  1. Double-click start.command in the whoop-pilot folder. It starts Whoop Pilot's server at http://localhost:8790/app/ (the window prints the address) and opens it in Chrome. Without Node.js it says so and runs the simulator only: no goggles video, recorder or house import.
  2. Chrome menu → Cast, save and share → Install page as app (or the install icon in the address bar) gives it its own window and Dock icon.
  3. Settings → Brain: paste a Claude API key from console.anthropic.com. It's stored only in this browser. Without a key, simple commands still work offline.
  4. Fly the Simulator first. Hold Space and say “take off”, then “find the cat”.
  5. Switch to Real drone → Connect radio (USB) (pick the radio's serial port) and Connect goggles. The pre-flight list turns green as things connect.
  6. Optional: Record (top right) keeps a flight's goggles video, telemetry and commands on this Mac; Settings → Recordings lists them.

4. Your house

With a capture of your house, Whoop Pilot knows the rooms by name, plans its way through the doors, keeps away from walls, fans and stairs, and flies missions: Go to a room or place, Look in a room, Find people, Check on pets, Patrol, Return home. You can try all of it in a simulator of your own house first.

Capture

  • Capture with SiteSpec (or Spacial). Walk every room the drone may fly in, slowly, with the doorways between them; include ceiling fans and stairs.
  • Leave the AprilTags up. Tag 0 on the floor becomes the home pad (where the drone takes off and lands), and the tags give the scan its true size.
  • Do the tape checks in SiteSpec (two or three long wall-to-wall distances). The drone keeps about 30 cm from walls; a scan 1% off is 6 cm off across a 6 m room.
  • Let SiteSpec finish the project so it draws the floor plan (rooms, doors).

Import and check

  1. Settings → House lists the captures in your SiteSpec and Spacial project folders, newest first. Click Use this capture. It copies the floor plan and the 3D scan into this browser (they stay on this Mac) and builds the flight map; it takes a few seconds. Choose a folder… takes a capture from somewhere else.
  2. Read what the import says: whether the scan and the floor plan agree in size, which doorways are wide enough, and anything to fix in SiteSpec.
  3. Rename the rooms there (Claude and the mission buttons use the names: “look in the kitchen”).
  4. On the map (under the camera view; ⇄ makes it large): Home moves the home pad (drag to set the way the drone faces), Landmark names a place (“cat bed”), No-fly draws a zone the drone must never enter, Fly here sends it to a spot.
  5. Simulator → My house: the camera shows your 3D scan, with people, a cat and a dog walking around (People & pets turns them off). Try every mission there first.

Alerts

Settings → Alerts: allow Mac notifications, and optionally enter an ntfy topic to get alerts on your phone (install the free ntfy app and subscribe to the same topic). Anyone who knows a topic can read its alerts and pictures, so use New private topic. What missions find also shows in Events next to the mission log, with a picture.

What “guard” really means. Whoop Pilot is supervised, not a security camera. Someone puts in a charged battery and arms the drone with the radio: the app never arms it. A sortie lasts about 3 minutes (the pack gives about 4 minutes of flight, and missions keep a margin to get home); the O4 also overheats after about 2.5 minutes sitting armed on the ground. The Mac, the radio and the goggles must be on, with this window visible.

5. First flight with your house, step by step

The same steps are in the app (Settings → House → First flight, step by step).

  1. Import the capture of your house (Settings → House).
  2. Build the 3D map and read the coverage: it lists the places the scan missed and how to rescan them. The drone never flies through space the scan didn't see.
  3. Optional: ask Claude to survey the house: room names, landmarks and hazards like ceiling fans, shown with their cost before anything is sent.
  4. Set the home pad with the map's Home tool and tape the printed mat there, its arrow the way the drone faces; keep 0.5 m around it clear.
  5. Rehearse in the simulator: My house → Rehearse the real flight, then Look in a room and Return home.
  6. Prepare before the battery goes in: Real drone → Ready to fly? → Prepare everything now (the models and the position database).
  7. Record a pad turn and a short flight by hand: Record, battery in, “The drone is on its home pad”, one slow full turn by hand on the pad, a minute's hover flown by hand, land on the pad, stop Record. Be quick: the O4 overheats after about 2.5 minutes on the ground.
  8. Calibrate the camera from that recording: Settings → House → Camera calibration → From a recorded flight → Calibrate from it, then Save it.
  9. Check localization on that recording: Settings → Recordings → Check localization; go on only when it passes.
  10. Pad check with the next battery: press “The drone is on its home pad”; the camera must match the 3D scan there.
  11. Measure braking in Full auto, in your largest open room (Settings → Flight); if it says there isn't room, missions stay at 0.3 m/s.
  12. First mission in Co-pilot: “Look in” one room, you hold the height, thumbs on the sticks. Full auto only after two good Co-pilot flights.
Honest limits. Flights are supervised and about 3 minutes long. The app never arms the drone: you do, with the radio. Keep the app's window visible while it flies. In real mode the app opens with Ready to fly?: what to do before the battery goes in, and what needs it in (the O4 camera overheats after about 2.5 minutes on the ground). Missions wait until nothing in it blocks them; voice moves still work.

The home pad mat

Print this at 100% (no scaling) and tape it to the floor where you set the home pad on the map, the arrow pointing the way the pad's arrow points on the map. Put the drone in the square, its nose at the arrow.

6. First real flight, by hand and by voice

Props spin fast even on a whoop. Fly in an open room, keep faces and pets back for the first flights, and keep your thumbs near the sticks.
  1. Start in Co-pilot mode: you hold height with the throttle, the AI steers. This is the reliable mode.
  2. Arm, take off by hand to about waist height, then flip SD down (your AI switch).
  3. Hold Space (or your PTT button) and say “look around and tell me what you see”.
  4. Then try “turn left 90”, “find the cat”, “go to the kitchen”. When it asks you to go lower or higher, do it with the throttle.
  5. Take over any time: flip SD up, or just move a stick (roll/pitch/yaw past ~30%, or the throttle about 1/8 of its travel). Esc or Stop in the app makes it hold still.
  6. If the app stops talking to the radio for 0.3 s, the radio beeps and vibrates and gives you the sticks back (in full-auto it first descends slowly, then idles). Flip SD up and down again to re-enable the AI.

Missions in your house

  1. Put the drone on its home pad, facing the way the pad's arrow points on the map, and click The drone is on its home pad in the Missions panel (it only works on the ground). That's where its position estimate starts, and on the real drone the camera is checked against the 3D scan there (the pad check). Until then the video shows NO POSITION · SET ON PAD: the drone still flies your commands, but nothing keeps it off walls and no-fly zones.
  2. Arm with the radio, flip SD down, and click a mission (or say it). In co-pilot mode it asks you to take off and land; it steers.
  3. It plans around the map, checks the battery before every leg, and holds still (co-pilot: asks you to take over) when it loses track of where it is. Stop, Esc, the AI switch or any stick takes over at once.
  4. While it flies, the video says why it is slow or holding back, and how sure it is of its position (POS ±, VISION). When it notices something the 3D scan doesn't have, possible change · check appears on the video: open it, look at the two pictures and decide (Confirm, Dismiss, or It was a person or pet). A change nobody decides on is treated as an obstacle.

Try it in the simulator first

Simulator → My house → Rehearse the real flight: the simulated drone then finds its position from its own camera (with the O4's blur, noise and a slightly wrong lens), live depth and the person detector run on its pictures, and missions start only when the real drone's vision would let them (the Ready to fly? list shows what is missing), at the real drone's lower speed limits. The map's layers show where the scan never saw (pink), where the drone flew (green to red as it grows unsure), the route ahead, people and obstacles; 3D shows the house in 3D, and History (next to Events) every flight's path, what it saw and what changed.

Full auto (the AI also flies height, take-off and landing) is experimental: a whoop has no height sensor, so height is estimated from the camera. Try it in the simulator first, then over carpet.

Troubleshooting

  • “Radio: no script”: USB-VCP isn't set to LUA, the script isn't added on the model's Mixer Scripts page, or you picked something other than USB Serial (VCP) when plugging in.
  • AI switch on but nothing moves: the Replace mix lines must use the same switch position as the AI sw input. Watch the Sticks panel: yellow dots are what goes to the quad.
  • Turns overshoot at first: it learns your real turn rate after a few turns. You can also enter your Betaflight rates in Settings → Flight.
  • Drifts a lot: it holds position using the camera image, which needs light and texture (not a blank wall). Fly in well-lit, furnished rooms.
  • Mission stopped when I switched windows: browsers slow down hidden tabs, so the app stops missions when hidden. Keep it visible (installing it as an app helps).
  • “Server not running” although its window is open: look at that window. Usually the usb package didn't install (cd tools && npm install), or a second copy of start.command found Whoop Pilot already running and quit, which is fine.
  • My house doesn't show in Settings → House: Whoop Pilot lists the projects in your SpaceBunny Projects, SiteSpec Projects and Spacial Projects folders, and in its own captures folder. Use Choose a folder… for one elsewhere, and pick the project folder (not its outputs folder): the picker selects folders, so the files in them show greyed out. Raw recordings (360 video, the iPhone scan) need processing in SpaceBunny first.
  • Missions say “I don't know where I am”: put the drone on the home pad and click The drone is on its home pad.
